# Requirements Log — zerocreds.ru

This is a historical implementation log. Status entries reflect the time they were recorded; use README.md and current tests for the live contract.

## Implemented

- zerocreds-server v0.1.0: self-hosted Node.js credential form server on port 3456.
- Nalog.ru: three-step headless Playwright flow (Gosuslugi login/password, 2FA, success).
- GitHub and Weeek CRM token forms; Tilda cookie-string form.
- `GET /version` exposes the Git commit for release verification.
- Hostland RU VM deployment at 178.212.14.192 with systemd; nginx routes `/connect/*` to port 3456 and `/` to static files.
- Dynamic Form API v0.2.0: `POST /api/session/create`, `GET /f/{token}`, and `POST /f/{token}`.
- Destinations: local file, Google Secret Manager (write-only `secretVersionAdder`), AWS Secrets Manager (`PutSecretValue`), and Vault.
- `GET /api/session/{token}/status` lets an agent check completion without seeing credentials.
- `ZEROCREDS_ADMIN_TOKEN` is required; only admin or active integrator tokens can create sessions.
- Google JWT auth avoids the SDK and uses `roles/secretmanager.secretVersionAdder`; AWS uses SigV4 and `PutSecretValue` without `GetSecretValue`.
- The old “Remember me” feature (`zc_uid` cookie and `~/zerocreds-saved/`) was removed in #50: it exposed secret fields in plaintext across integrators. Password show/hide and Paste controls remain.
- #50 security hardening: SHA-256-indexed integrator registry, constant-time admin comparison, pending registration approval, reverse-proxy IP rate limiting, global error boundary, 413 body-size response, strict input validation, HTML escaping including descriptions, 32-hex form token, nonce CSP, frame protection, no-referrer, and no-store.
- #50 destination policy: named destinations by default; inline destinations require `ZEROCREDS_ALLOW_INLINE_DESTINATIONS=1`. HTTPS `http_post` hosts must be allowlisted; private, loopback, and link-local addresses are blocked at connect time unless the development override is set. Upstream response bodies are not returned.
- #50 form disclosure: requester and exact destination appear above Submit, without a “write-only” claim for readable destinations. Integrator local files are separated under `~/agent-tokens/_integrators/{id}/`. One-time links are claimed atomically; expired files are swept; directories use mode 0700; status is owner-scoped. Nalog screenshots and page-text logging were removed.
- Z0 CI/CD guard (#51): removed auto-merge; production deployment requires a reviewer and passing tests on the same main SHA. Server and MCP use lockfiles and `npm ci`; Node 22, dependency audit, gitleaks, syntax checks, and SHA-pinned Actions were added.
- Z8 form design (#59): system-aware light/dark mode with a persisted toggle, mobile input sizing and sticky Submit, and CSP-compatible markup. Screenshots are generated by `server/scripts/form-screenshots.js`.
- #114 discovery: candidate refs distinguish Keychain services and preview results are deduplicated; the catalog compares ref sets. Legacy Keychain records missing `service` are cleaned during writes. Categories include credential, Wi-Fi, Bluetooth, Apple system, browser, VPN, and other. Preview returns category counts and optional category filters without hiding anything by default.
- #114 verification: arbitrary provider slugs return `unsupported_provider` instead of schema errors; provider and account aliases are validated. README and MCP descriptions now cover discovery TTL, one-use previews, search scope, and provider support.
- #114 local setup: `setup-local-mac.sh` writes the V2 `mcp.servers.zerocreds` shape and migrates the legacy flat format.
- #116 stable refs: the service discriminator affects hashes only when present, preventing existing GitHub, Cloudflare, and Google Cloud records from being orphaned.
- #117 deploy incident: a production approval pending since 2026-10-16 held the concurrency group while new runs canceled each other. The stale run was canceled and commit `df1e075` deployed and checked at `/version`.
- #119 MCP tool names no longer repeat the provider name. Local URL is `http://localhost/zerocreds`; the server accepts the mounted prefix and builds links from the full base URL. A loopback-only proxy on port 80 rewrites Host to localhost; setup installs it when passwordless sudo is available or prints manual commands. `/about` displays the actual deployment address.
- #123 post-submit confirmation shows the exact storage target (for example, macOS Keychain on this Mac), which previously disappeared with the form.

## Planned at the time of this log

- Rate limits for session creation and submission; an index instead of full pending-file scans.
- Detect stale production deployments in the scheduled public monitor. `check-public.py` compares the expected commit only when `EXPECTED_COMMIT` is supplied; this missed the three-day lag in #117. Balance in-progress deploys against an age threshold.
- Russian zerocreds.ru landing page, Hostland DNS migration, Let's Encrypt certificate, trained-assist-agent form links, and a Tilda HTML-block snippet. These are historical plans, not current release promises.

- Cloud Run and Yandex Cloud Functions for stateful Nalog Playwright sessions.
